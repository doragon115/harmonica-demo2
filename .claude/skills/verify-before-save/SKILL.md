## 鉄則

「修正した」と宣言する前に、必ず差分を自分の目で確認する。
差分が空なら修正は行われていない。名前に `fixed` と付けても中身は直らない。

## コミット前の確認手順

```bash
# 変更があるファイルの一覧
git status

# 実際の差分(これが空なら何も変わっていない!)
git diff

# ステージ済みの差分
git diff --cached
```

## 差分が空だった時の対応

「変更がありませんでした」と正直に報告する。
意図した修正がなぜ反映されていないかを調べる(別ファイルを編集していた、
編集が保存されていなかった、など)。**空のままコミットしない。**

## 差分の中身の確認

差分があっても安心しない。
- 意図した箇所**だけ**が変わっているか
- 意図していない削除・文字化け・インデント崩れが混ざっていないか
を確認してからコミットする。

## 報告の作法

ユーザーへ「修正しました」と報告する時は、
何行変えたか・どこを変えたかを1〜2行で添える。
例:「`resume()` の後に再描画を追加(1行、444行目)」。
これにより「実は変わっていない」報告が構造的に不可能になる。
