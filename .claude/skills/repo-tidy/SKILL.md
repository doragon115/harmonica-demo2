## 手順(必ずこの順番・飛ばさない)

1. **現状調査**: `md5sum` で完全一致を特定、`diff` で近い物同士の差分を確認
2. **分類表を作る**: 各ファイルを「正本候補 / 完全重複 / 旧版 / 実験用」に分類し、根拠を書く
3. **ユーザーに分類表を見せて削除の許可を得る**(ここを飛ばして削除しない)
4. **許可が出たら削除**し、正本を分かりやすい名前(例: `index.html`)にリネームする提案をする
5. **1コミットにまとめ**、メッセージに「何を残し何を消したか」を書く

## 正本の選定基準

(a) 機能的に最新か、(b) 動作確認済みか、(c) 差分比較で
他のコピーの変更をすべて含んでいるか。
ファイル名の `final` は信用しない
(実例: `_final_restored` と `_working_ios` は完全同一だった)。

## 調査コマンド

```bash
md5sum * | sort            # 完全一致の検出
diff fileA fileB           # 差分確認
git log --oneline -- file  # 各ファイルの履歴
```

## 消してよい物・ダメな物

- **完全同一の重複** → 正本1本を残して削除してよい(要ユーザー許可)
- **差分のある旧版** → gitに履歴があることを確認してから削除(要ユーザー許可)
- **実験ファイル** → 中に固有の知見があればスキルやメモに移してから削除
- **自分が作っていないファイルで用途不明の物** → 削除せずユーザーに確認

## 削除後の確認

残した正本が単体で動くことを確認してから完了報告する。
