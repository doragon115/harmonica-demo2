# 指示書11【パソコン上で実行】4月1日以降のセッションログ分析

## この指示書だけ他と違う点

01〜10はこのリポジトリ内にスキルを作る作業だが、この指示書は
**ユーザーのパソコン上のClaude Codeで実行する**分析作業。
クラウド環境からはパソコン内のセッションログが読めないため、
本物の「回り道の軌跡」はパソコン上でしか分析できない。

## 目的

`~/.claude/projects/` に残っている4月1日以降の全セッションログから
回り道(試行錯誤・やり直し・同じ失敗の繰り返し)を抽出し、
新しいスキル提案を追加で書き出す。

## 前提知識

- Claude Codeのセッションログは `~/.claude/projects/<プロジェクト名>/<セッションID>.jsonl` にある
- 1行が1イベント(ユーザー発言・アシスタント発言・ツール実行など)のJSON
- ファイルの更新日時がセッションの日時に対応する

## 手順

### 手順1: 対象ログの一覧を作る

```bash
find ~/.claude/projects -name "*.jsonl" -newermt "2026-04-01" -exec ls -la {} \;
```

(4月1日が2025年の意味なら `2025-04-01` に変える。ユーザーに確認すること)

### 手順2: 各セッションの規模を把握する

```bash
for f in $(find ~/.claude/projects -name "*.jsonl" -newermt "2026-04-01"); do
  echo "$f : $(wc -l < $f) イベント"
done | sort -t: -k2 -rn | head -20
```

イベント数が多いセッション上位から順に読む(回り道は長いセッションに潜む)。

### 手順3: 回り道のサインを探す

各ログで以下のパターンを数える:

```bash
# 同じファイルへの編集回数(5回以上なら試行錯誤の疑い)
grep -o '"file_path":"[^"]*"' <ログファイル> | sort | uniq -c | sort -rn | head

# エラーの繰り返し
grep -c '"is_error":true' <ログファイル>

# ユーザーによる中断・訂正(「違う」「そうじゃなくて」「やり直し」など)
grep -c -E '違う|そうじゃな|やり直|戻して|また同じ' <ログファイル>
```

### 手順4: 回り道と判断する基準

以下のどれかに当てはまる箇所をメモする:
- 同じファイルを5回以上編集して最終差分が小さい(=試行錯誤)
- 同じ種類のエラーが3回以上出ている(=知識不足の定番問題)
- ユーザーが同じ趣旨の指示を2回以上言い直している(=指示の解釈ミス)
- セッションの最後に「結局〇〇だけだった」という発見がある(=近道があった)

### 手順5: レポートを書く

`docs/skill-proposals/session-log-report.md` に以下の形式でまとめる:

```markdown
# セッションログ分析レポート(4月1日〜)
## 分析対象: N セッション
## 回り道一覧
| 日付 | プロジェクト | 症状 | かかった規模 | 本当の原因 |
|---|---|---|---|---|
## 追加スキル提案
| スキル名案 | 防げる回り道 | 優先度 |
```

### 手順6: 追加提案を指示書化する

見つかった回り道ごとに、この `instructions/` フォルダの01〜10と同じ形式
(目的/背景/フロントマター/含める内容/完了条件)で指示書を追加する。
番号は12から連番。既存の01〜10と重複する提案は作らず、既存指示書の「背景」に
実例を追記する。

## やってはいけないこと

- ログの中身(会話内容)をレポートに長々と貼らない。要約だけにする
  (ログには個人情報や他プロジェクトの情報が含まれうるため)
- 分析のためにログファイル自体をリポジトリにコミットしない(絶対禁止)
