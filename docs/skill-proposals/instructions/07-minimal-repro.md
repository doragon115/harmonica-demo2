# 指示書07【優先度★】minimal-repro スキルの作成

## 目的

バグ調査用の「最小再現ファイル」を正しい場所に作り、解決後は知見を残して片付ける。

## 背景

音が鳴らない問題の調査で `test.html` と `harmonica-ios.html` が本番リポジトリ直下に
作られ、解決後もそのまま残った。ファイル自体は良い調査手法だが、置き場所と後始末が
なかったため、リポジトリに「これは何?」というファイルが増えた。

## 作成するファイル

`.claude/skills/minimal-repro/SKILL.md`

## フロントマター(このまま使う)

```markdown
---
name: minimal-repro
description: バグの原因を切り分けるために最小限のテストファイル・再現コードを作る時に読む。test.html や debug.js のような一時ファイルを作りそうになった時の作法。
---
```

## SKILL.md 本文に含める内容(全部入れる)

1. **作る前に**: まず既知の定番問題でないか関連スキル(ios-audio-unlock等)を確認する。
   定番問題ならチェックリストを潰す方が最小再現を作るより速い。

2. **置き場所**: 最小再現ファイルはリポジトリ直下に置かない。
   - Claude Codeのscratchpadディレクトリ(セッション専用の一時領域)が第一候補
   - リポジトリ内に置く必要がある場合(実機から開く等)は `debug/` ディレクトリを
     作ってそこに置き、コミットしない(コミット前に削除するのが原則)

3. **作り方**: 疑っている要素を1つだけ含む、可能な限り小さいファイルにする。
   ファイル名は `repro-<何の再現か>.html` のように用途が分かる名前にする
   (`test.html` のような無情報な名前を避ける)。

4. **解決後の後始末**(必須):
   1. 分かった原因と対策を、該当スキルへの追記または新スキル提案としてメモする
   2. 最小再現ファイルを削除する
   3. 「原因は◯◯でした。再現ファイルは削除済み」とユーザーに報告する

5. **例外**: ユーザーが「テストページとして残したい」と言った場合は、
   分かりやすい名前に変えて残す(その場合はコミットしてよい)。
