# 指示書08【優先度★】commit-messages-ja スキルの作成

## 目的

後から軌跡を追える、意味のあるコミットメッセージを毎回書く。

## 背景

このリポジトリのコミット8件はすべて「Add files via upload」で、
どのコミットで何が直ったのか・なぜファイルが増えたのかを後から追う手段がなかった。
今回の分析でも、md5チェックサムとdiffで軌跡を復元する手間が発生した。

## 作成するファイル

`.claude/skills/commit-messages-ja/SKILL.md`

## フロントマター(このまま使う)

```markdown
---
name: commit-messages-ja
description: git commit する時に毎回読む。コミットメッセージの書き方の基準。
---
```

## SKILL.md 本文に含める内容(全部入れる)

1. **形式**: 1行目に「何をしたか」を日本語で具体的に。必要なら空行を挟んで
   「なぜ」を2〜3行で書く。

   ```
   iOS Safariで音が鳴らない問題を修正

   AudioContextのresume()完了後に再描画していなかったため、
   アンロック後も画面が操作を受け付けなかった。resume().then()内で
   renderHarmonica()を呼ぶよう変更(1行)。
   ```

2. **禁止例と修正例**(表で載せる):
   - 「Add files via upload」→「ハーモニカ配列表アプリの初版を追加」
   - 「fix」→「ベンド音の周波数が半音ずれていたのを修正」
   - 「update」→「iPad向けにタップ領域を44pxに拡大」

3. **1コミット=1目的**: 無関係な変更を混ぜない。混ざりそうなら分割する。

4. **コミット前チェック**: verify-before-save スキルに従い `git diff` を確認してから
   メッセージを書く(差分を見れば自然と具体的なメッセージになる)。
