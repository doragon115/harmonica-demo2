# 指示書03【優先度★★★】verify-before-save スキルの作成

## 目的

「修正したつもりが実は何も変わっていないファイル」を保存・コミット・アップロードするのを防ぐ。

## 背景

過去の作業で、**元ファイルとmd5が完全一致するファイル**が `_full_fixed` という名前で
アップロードされていた(=40分の作業で変更ゼロ)。さらに別の1組も完全一致。
「直したはず」の確認をせずに保存したことで、無意味な周回が2回発生した。

## 作成するファイル

`.claude/skills/verify-before-save/SKILL.md`

## フロントマター(このまま使う)

```markdown
---
name: verify-before-save
description: ファイルの修正を終えて保存・コミット・アップロード・デプロイする直前に必ず読む。「修正版」「fixed」「直した」と言ってファイルを確定させる前のチェック。
---
```

## SKILL.md 本文に含める内容(全部入れる)

1. **鉄則**: 「修正した」と宣言する前に、必ず差分を自分の目で確認する。
   差分が空なら修正は行われていない。名前に `fixed` と付けても中身は直らない。

2. **コミット前の確認手順**(このまま載せる):

   ```bash
   # 変更があるファイルの一覧
   git status
   # 実際の差分(これが空なら何も変わっていない!)
   git diff
   # ステージ済みの差分
   git diff --cached
   ```

3. **差分が空だった時の対応**: 「変更がありませんでした」と正直に報告する。
   意図した修正がなぜ反映されていないかを調べる(別ファイルを編集していた、
   編集が保存されていなかった、など)。**空のままコミットしない。**

4. **差分の中身の確認**: 差分があっても安心しない。
   - 意図した箇所**だけ**が変わっているか
   - 意図していない削除・文字化け・インデント崩れが混ざっていないか
   を確認してからコミットする。

5. **報告の作法**: ユーザーへ「修正しました」と報告する時は、
   何行変えたか・どこを変えたかを1〜2行で添える。
   例:「`resume()` の後に再描画を追加(1行、444行目)」。
   これにより「実は変わっていない」報告が構造的に不可能になる。
