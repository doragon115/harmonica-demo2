# 指示書02【優先度★★★】single-source-versioning スキルの作成

## 目的

「ファイルをコピーして `_fixed` `_final` を付ける」版管理をやめさせ、
正本1本+gitコミットで履歴を残す習慣に切り替える。

## 背景

このリポジトリには同じアプリのコピーが6本ある(`_full_fixed` `_working_ios`
`_final_mobile` `_final_restored` `_ipad_ok`)。うち2組はバイト単位で完全に同一。
「どれが最新の正しい版か」が分からなくなり、修正のたびに間違ったファイルを
触るリスクが生まれていた。gitがあるのだから複製は一切不要だった。

## 作成するファイル

`.claude/skills/single-source-versioning/SKILL.md`

## フロントマター(このまま使う)

```markdown
---
name: single-source-versioning
description: ファイルを修正・改善する時、または「前の版を残しておきたい」「バックアップを取ってから直したい」と言われた時に必ず読む。_fixed _final _backup _old _v2 などの複製ファイルを作りそうになった時のガードレール。
---
```

## SKILL.md 本文に含める内容(全部入れる)

1. **絶対ルール**: 修正版を作る時は既存ファイルを**その場で編集**する。
   `xxx_fixed.html` `xxx_final.html` `xxx_v2.html` のような複製は作らない。
   過去の版に戻りたければ `git log` と `git checkout <コミット> -- <ファイル>` で戻れる。

2. **ユーザーに「コピーを取って」と言われた時の対応**:
   複製ファイルではなく「gitに履歴が残っているのでいつでも戻せます」と説明し、
   編集前に `git add -A && git commit -m "変更前のスナップショット"` を提案する。
   それでもユーザーが複製を望む場合のみ複製する(ユーザーの意思が最優先)。

3. **危険なファイル名の検知**: 作業開始時にリポジトリ内に
   `_fixed` `_final` `_old` `_backup` `_copy` `_restored` `_ok` `_v[0-9]` を含む
   ファイル名を見つけたら、「正本がどれか分からなくなる兆候」としてユーザーに報告し、
   repo-tidy スキル(あれば)による統合を提案する。

4. **正本の決め方**: 複数コピーが既にある場合、(a) 中身のdiffを取り、
   (b) 機能的に最新のものを特定し、(c) ユーザーに「これを正本にしてよいか」確認してから
   1本に統合する。無断で削除しない。

5. **確認コマンド集**(このまま載せる):

   ```bash
   # 完全に同一のファイルを見つける
   md5sum *.html | sort
   # 2ファイルの差分を確認する
   diff fileA.html fileB.html
   # 過去の版に戻す
   git log --oneline -- <ファイル名>
   git checkout <コミットID> -- <ファイル名>
   ```
